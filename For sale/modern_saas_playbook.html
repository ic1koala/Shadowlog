本ドキュメントは、Next.js、GitHub、Vercel、Supabase、および外部決済・生成AI APIを組み合わせてWebサービス（SaaS）を迅速かつ安全に立ち上げ・スケールさせるためのシステム設計アーキテクチャ（0.0秒先読み・コンテンツバンク・自動レスキュー同期）およびプロジェクト推進（4ロール分業・勝手に直さないガバナンス・抜け漏れ防止4大プロトコル・2フェーズ原価管理）を体系化した汎用プレイブックです。特定のサービス名に依存せず、新規事業の立ち上げ時に標準テンプレートとしてそのまま活用できます。

2. オフラインファースト ＆ 未同期データの「自動レスキュー同期」設計

① ゲスト体験 (登録不要): 最初の数回は登録不要で即時利用可能にし、LocalStorageへ一時保存して離脱を防止。
② リアルタイム保存 ＋ 自動レスキュー同期: アクション完了時にローカル保存と同時にSupabaseへ即時INSERT。さらに画面起動時に「ローカルにあるがクラウドに未反映のレコード（localOnly）」を自動検出し、バックグラウンドでクラウドへ救出同期する。

3. 生成AIの「5秒待ち」を「0.0秒」にするハイブリッド先読み＆バンク設計

LLMや音声合成（TTS）はリアルタイム生成すると3〜5秒の待ち時間が発生し、API原価もかさみます。以下の2段階設計で「体感待ち時間 0.0秒」と「API変動原価 70〜80%削減」を同時達成します。

⚡ ① クライアント1件先読み (Prefetch)

1問目を操作中に裏側（非同期）で「次の1問（テキスト＋音声）」を先読みしてメモリ保持。「次へ」を押した瞬間に待ち時間 0.0秒 で即時表示。

🏦 ② DBバンク蓄積 ＆ 週次10%入れ替え

ユーザー利用の裏で生成データをDB（各カテゴリ上限300件）に蓄積。上限到達後はDBから0.1秒・原価0円で配信し、毎週1回「使用回数上位10%」だけを季節・最新トレンド入りで入れ替え。

2

セキュリティ ＆ データ整合性の鉄則

🔒 1. Row Level Security (RLS) ＆ 管理者権限の単一厳格化

全テーブルでRLSを有効化し、本人のみ読み書きを許可。管理者画面（/admin/*）やテストモードの判定（isAdminEmail）は、開発用ダミーアドレスを残さず本番オーナーの単一メールアドレスのみに厳格化する。

ALTER TABLE public.user_data ENABLE ROW LEVEL SECURITY;
CREATE POLICY "User owns data" ON public.user_data FOR ALL USING (auth.uid() = user_id);

💳 2. 決済情報の完全非保持化 (PCI-DSS準拠)

  • Stripe Checkout / Customer Portal の全面採用により、カード情報はStripe内で完結。
  • Webhookイベント（課金成功・解約・期限切れ）を受信してSupabaseのプランステータスを自動更新。
  • 特定商取引法に基づく表記（/tokushoho）は全画面フッターで目立たせず、決済モーダル・ログイン導線に適切配置。

⚙️ 3. サーバーレス環境での永続化と環境変数多段フォールバック

VercelのServerless Functionsは数分でコンテナが破棄されるため、アクセス解析（PV/UU）等はメモリ変数（Map）ではなく必ずSupabase（daily_analytics等）へ日次UPSERT永続化する。また、Vercel連携時の環境変数重複プレフィックスに備え、初期化コードには多段キーフォールバックを実装する。

1. 4ロール分業体制（オーナー × 統括PM × 技術相談 × 実務実装）

① オーナー / PO
最高意思決定

【鉄則1】「勝手に直さない」意思決定プロトコル
  1. 検知: 問題や不整合箇所を特定。
  2. 提案: 修正案A/Bと影響を整理して提示。
  3. 判断: オーナーの承認を得る。
  4. 着手: 承認後に実装・テスト・報告。
【鉄則2】抜け漏れゼロの「4大プロトコル」
  1. 即時復唱: 会話の場で優先度と時期を合意。
  2. 即時起票: その場で FEEDBACK_LOG.md へ記録。
  3. 定期スキャン: 毎週月曜朝に未着手項目を点検。
  4. HTML可視化: 統括ダッシュボードへ即時同期。
🧪 本番環境を汚さない「管理者限定プレビュー（Feature Toggle）」方式:
新UIや実験的機能（例: チャンク区切り表示や新録音方式）は、まず管理者アカウント（isAdminEmail / 🧪テストボタンモード）限定で本番に表示してオーナーが実機検証し、完成度を確認してから全ユーザー標準ONへ昇格させる。

事業採算・2フェーズ原価管理 ＆ リスク自動計算ノウハウ

1. 2フェーズ原価管理モデル（蓄積期 ➔ バンク定常運用期）

生成AIを組み込むSaaSでは、「蓄積期（Phase A）」と「バンク定常期（Phase B）」の2段階で原価と営業利益率を管理します。

📘 フェーズA：バンク蓄積期（保守上限）
各スロットが上限（300件）に達するまでの期間。都度生成＋解析で1回あたり約0.322円。50名規模での営業利益率は約55〜58%。管理画面の安全監視基準に採用。
🏦 フェーズB：バンク定常期（本命）
上限到達後はDBから0円で配信し、解析のみ（約0.097円/回、原価70%超削減）＋週10%入替（月額固定約331円）。営業利益率は約79〜80%へ向上！

2. 顧客管理画面（/admin/customers）の4大モニタリング機能

有料プランを「使い放題」として提供しつつ、管理画面で各顧客の利用ペース・日次推移・監査ログを一元監視します。

月間損益分岐回数 = (月額料金 - Stripe手数料 3.6%) ÷ 1回原価 ／ 1日限界回数 = 月間損益分岐回数 ÷ 30日
🟢 安全 (Safe)
限界の50%未満利用
🟡 注意 (Warning)
限界の50%〜80%利用
🔴 警戒 (Danger)
限界の80%以上利用
  • メンバー別「日次利用回数折れ線グラフ」モーダル: 利用回数ボタンから日別推移グラフ＋合計・平均・最高記録を即時表示。
  • プラン別内訳（Pro/Basic）＆ モバイルカード表示切替 ＆ コンプライアンス監査ログタブ統合。
