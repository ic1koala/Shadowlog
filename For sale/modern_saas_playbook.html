【本ドキュメントの目的】
本ドキュメントは、Next.js、GitHub、Vercel、Supabase、および外部決済・AI APIを組み合わせてWebサービス（SaaS）を迅速かつ安全に立ち上げ・スケールさせるためのシステム設計アーキテクチャおよびプロジェクト推進（やること管理・意思決定）のノウハウを体系化した汎用プレイブックです。特定のサービス名やドメインに依存せず、新規事業の立ち上げ時に標準テンプレートとして活用できます。

2. オフラインファースト ＆ クラウド二重化設計

B2Cや習慣化SaaSでは、「ネット環境が不安定でも快適に動く」「登録前にすぐ試せる」ことがCVR（登録率）と継続率を大きく左右します。

① ゲスト体験: 登録不要で即時利用可能にし、LocalStorage/IndexedDBへ一時保存（超高速・離脱防止）。
② クラウド自動移行: 会員登録・ログインが完了した瞬間に、端末内の利用履歴をSupabaseへ一括自動アップロード。
③ 複数端末同期: PCやスマホのログイン時にクラウドから最新データを自動ダウンロードし、差分をマージ。
2

セキュリティ ＆ データ整合性の鉄則

🔒 1. Row Level Security (RLS) の徹底

Supabaseではフロントエンドから直接DB操作が可能ですが、全テーブルでRLSを有効化しないと他人のデータが丸見えになります。

-- 本人のみ読み書きを許可するポリシー例
ALTER TABLE public.user_data ENABLE ROW LEVEL SECURITY;
CREATE POLICY "User owns data" ON public.user_data FOR ALL USING (auth.uid() = user_id);

※ 管理者集計や定期バッチは、サーバーサイドAPIからのみ SUPABASE_SERVICE_ROLE_KEY を使用して実行する。

💳 2. 決済情報の完全非保持化 (PCI-DSS準拠)

自社サーバーにクレジットカード番号を保持・通過させることはセキュリティ・法務上絶対に避けるべきです。

  • Stripe Checkout / Customer Portal の全面採用により、カード情報はStripe内で完結。
  • 自社DBには「Stripe顧客ID（cus_xxx）」のみを紐付け、カード番号は一切持たない。
  • Webhookイベント（課金成功・解約・期限切れ）を受信してSupabaseのプランステータスを自動更新。

⚙️ 3. サーバーレス環境での状態管理（インメモリ禁止）

VercelのServerless Functionsはアクセスごとに異なるコンテナが起動し、数分アクセスがないと破棄されます。 「メモリ上の変数（Mapなど）に保存したデータは再起動・デプロイで必ず消える」ため、アクセスログや状態値は必ずSupabaseやRedisなどの外部DBへ永続化する。

プロジェクト推進 ＆ 「やること管理」ノウハウ

1. 3層マネジメント分業体制

① オーナー / PO
最高意思決定
事業方針・最終承認
② 統括担当 / PM
要件定義・仕様書作成
試算・品質監査
③ 実務担当 / エンジニア
コード実装・単体テスト
ビルド検証・デプロイ
【最重要鉄則】「勝手に直さない」意思決定プロトコル
開発中に問題や不整合を発見しても、実装者は勝手にコードを書き換えてはならない。
  1. 検知: どこに何の懸念・問題があるかを特定。
  2. 提案: 修正案・選択肢を整理して提示。
  3. 判断: オーナーの確認・承認を得る。
  4. 着手: 承認後に初めて実装を行い、テスト確認を経て完了報告する。
これにより、「意図と異なる改修」や「仕様の先祖返り」を完全に防止できる。

事業採算・コスト管理 ＆ リスク自動計算ノウハウ

1. API従量課金SaaSの原価シミュレーション

AIやSMSなどの従量課金APIを組み込む場合、概算ではなく「1リクエストあたりの実測原価」を厳密に計算します。

実測ベースの単価算出:
トークン数、録音秒数、文字数を実測し、1ドル150円等の為替レートで1回あたりの原価を算出（例: 1回約0.32円）。
キャッシュ再利用による圧縮:
同一入力の再試行時は生成済みオブジェクトをメモリキャッシュから再利用し、2回目以降のコストを0円にする。

2. 顧客ごとの損益分岐点（採算限界）自動計算式

有料プランを「使い放題」として提供する場合、管理画面で各顧客の利用ペースと赤字化リスクを自動計算させます。

月間損益分岐回数 = (月額料金 - Stripe手数料 3.6%) ÷ 1回あたり原価
1日あたり限界回数 = 月間損益分岐回数 ÷ 30日
🟢 安全 (Safe)
限界の50%未満利用
🟡 注意 (Warning)
限界の50%〜80%利用
🔴 警戒 (Danger)
限界の80%以上利用
